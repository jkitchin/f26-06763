# Week 08 — Mini-Project Week (dedicated studio + demos)
**Arc:** Bridge between *ML / deep learning* and *LLM & agentic engineering* · **Sessions:** MP-1 (build/studio) + MP-2 (demos)

**Prerequisites (from prior weeks):** Everything in Weeks 1–7 — a reproducible `uv` project (Wk1), data storage & validated pipelines (Wk2–3), leakage-safe features and splits (Wk4), the ML workflow with MLflow tracking (Wk5), PyTorch training (Wk6), and surrogate modeling / uncertainty quantification / Bayesian optimization (Wk7).

This is a **dedicated week with no new lecture content**. Both class days are given to the **surrogate-model miniproject (A7)** that launched in Week 7: one **build/studio day** and one **demo day**. It is the integrative checkpoint of the first half of the course — students take an engineering dataset all the way from data → trained surrogate → honest, uncertainty-aware evaluation before the course pivots to LLMs and agents. The miniproject is **due at the end of this week**; full spec and rubric are in `miniproject.md` (15% of the course grade).

## Module learning objectives
- Integrate the first-half toolchain (data → features → model → evaluation → tracking) into one coherent, reproducible artifact.
- Diagnose and fix real end-to-end issues (leakage, broken splits, mis-scaled inputs, under-tracked runs) under time pressure, with instructor/peer help.
- Communicate an engineering ML result honestly — including uncertainty and failure cases — in a short demo.

## Session MP-1 — Build / studio day
**Purpose:** Supervised, hands-on work time to get the miniproject running end-to-end, with the instructor and TAs acting as a clinic.

**How the day runs:**
- Brief (~10 min) kickoff: the five things a complete submission must show — validated data pipeline, a strong baseline, a surrogate/DL model, calibrated uncertainty, and MLflow-tracked runs (git SHA + data hash + seed).
- Studio work: students build; instructor/TAs circulate.
- Rotating **clinic slots** (~10–15 min/student or team): demo current state, get one blocking-issue triage and one concrete next step.
- Targeted **mini-huddles** grouping students stuck on the same issue (e.g., extrapolation hold-out, UQ calibration, MLflow logging).

**Common blockers to pre-empt:** train/test leakage via features fit on the full set; random splits where a grouped/temporal split is required; uncertainty that isn't calibrated; runs that aren't reproducible from a clean checkout.

**Engineering framing / dataset:** Each student's chosen engineering dataset from Week 7 (e.g., power-plant output, airfoil self-noise, concrete strength, turbofan RUL, or an approved bring-your-own dataset with recorded source/version/hash).

## Session MP-2 — Demo day
**Format:** Short **miniproject demos** — each student/team gives a **~5-minute code + results walkthrough + ~2 minutes Q&A** (adjust to enrollment; hard-stop timing).

**What each demo must show (mirrors the miniproject rubric):**
1. The engineering problem and dataset (what is being predicted and why it matters) — brief.
2. Data pipeline and the split strategy (and why it avoids leakage) — brief.
3. Baseline vs. surrogate/DL model, with the key metric on the untouched test set.
4. **Uncertainty**: how it was produced and whether it is calibrated; behavior on an **extrapolation hold-out**.
5. One honest failure or limitation and what you'd do next.

**Peer feedback:** Non-presenting students submit a short structured peer review for ≥3 demos (one strength, one concrete suggestion, a 1–5 score on rigor + clarity). Advisory; counts toward reviewer participation.

## Assignment / deliverable
The **miniproject (A7)** is **due at the end of Week 8** — repository, short report, and recorded walkthrough per `miniproject.md`. No separate weekly assignment this week. The Week-9 LLM arc assumes the miniproject is complete and its surrogate is available (it reappears as a callable agent tool in Week 11).

## Teaching notes / common pitfalls
- **Protect the studio as work time.** MP-1 pays off only if students arrive with something that already runs; require a runnable skeleton so clinic slots go to real blockers.
- **Reward honesty over polish.** In demos, a well-characterized failure and calibrated uncertainty should score better than an over-claimed "great" MAE with no error analysis.
- **Watch the leakage epidemic.** This is where first-half leakage habits surface; make the split-and-fit discipline an explicit demo requirement.
- **This is a real deadline, not a soft checkpoint.** The course pivots to a new arc next week; keep the miniproject due date firm so it doesn't bleed into the LLM block.
- **Bridge forward.** Close MP-2 by noting that the same evaluation discipline (honest metrics, held-out regimes, uncertainty) is exactly what the LLM/agentic and production arcs will demand next.
