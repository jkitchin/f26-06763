# Week 04 — Feature Engineering & Data-Centric ML
**Arc:** Data Systems · **Lectures:** L7–L8

**Prerequisites (from prior weeks):** Reproducible `uv`/git project and MLflow (Wk1); storage in PostgreSQL/Parquet/DuckDB (Wk2); a validated batch pipeline with pandera/GE (Wk3). Familiarity with pandas/Polars transforms.

## Module learning objectives
- Engineer features for time-series and physical data: lags, rolling statistics, spectral/summary features, and domain transforms.
- Apply scaling/normalization correctly and fit all transforms on training data only.
- Identify and eliminate data leakage, including target leakage and temporal/group leakage in splits.
- Design correct train/validation/test splits for time-series and grouped (per-unit) data.
- Version datasets and feature sets so an experiment can be reproduced from raw data to model input.
- Iterate data-centrically: improve data/labels/features rather than only tuning the model, and measure the effect.

## Lecture L7 — Features for time-series and physical data
**Objectives:**
- Construct lag, window, and frequency-domain features for sensor/simulation signals.
- Apply appropriate scaling and encoding while avoiding leakage.
- Assemble features into a reproducible feature pipeline with fitted transformers.

**Topics:**
- Time-series features: lags, differences, rolling mean/std/min/max, expanding windows, rate-of-change, time-since-event; resampling irregular sensor data to a fixed grid.
- Physical/domain features: dimensionless groups, energy/power derived quantities, calibration corrections, unit consistency; spectral features (FFT band energy) for vibration/acoustic signals.
- Scaling and encoding: standardization vs. min-max vs. robust scaling; why fit-on-train-only matters; log/Box-Cox transforms for skewed physical quantities; categorical encoding for equipment/regime IDs.
- Building a leakage-safe pipeline: scikit-learn `Pipeline`/`ColumnTransformer` (or equivalent) so fitting happens inside the training fold only; persisting fitted transformers as artifacts.
- Feature stores (concept): why teams centralize feature definitions; not built here.

**Live demo / in-class activity:** On NASA C-MAPSS turbofan data, build features per engine unit — rolling means/stds of key sensors, deltas from cycle 1, and a smoothed degradation trend — then show the *wrong* way (scaling over the full dataset) vs. the *right* way (scaler fit on training units only) and quantify the difference in a quick RUL baseline.

**Engineering framing / dataset:** NASA C-MAPSS Turbofan Engine Degradation Simulation (FD001–FD004): run-to-failure multivariate sensor trajectories for fleets of simulated engines, standard Remaining-Useful-Life (RUL) benchmark. Natural per-unit grouping and strong temporal structure — ideal for teaching windows, splits, and leakage.

**Readings & resources:**
- scikit-learn User Guide, "Preprocessing data" and "Pipeline / ColumnTransformer."
- tsfresh documentation, "Overview on extracted features" (for time-series feature vocabulary).
- Saxena et al., "Damage Propagation Modeling for Aircraft Engine Run-to-Failure Simulation" (PHM 2008) — the C-MAPSS dataset paper.
- A. Ng, "Data-Centric AI" resources / MLSys community talks.

## Lecture L8 — Data quality, versioning, splits, and data-centric iteration
**Objectives:**
- Design leakage-free splits for temporal and grouped data and detect leakage empirically.
- Version datasets and feature sets so results are reproducible from raw inputs.
- Run a data-centric improvement loop and attribute gains to data changes.

**Topics:**
- Splits done right: time-based splits, group/unit-based splits (no engine in both train and test), nested CV for time-series; the danger of random shuffling on temporal data.
- Leakage taxonomy: target leakage (feature encodes the label), train/test contamination (scaling/imputation over all data), temporal leakage (using the future), group leakage; how to audit for each.
- Data versioning: DVC (or `git-lfs`) to track datasets and feature artifacts alongside code; content hashing, `dvc.yaml` pipeline stages, reproducing a run from a commit; linking dataset version + code version + MLflow run.
- Data documentation: Datasheets for Datasets, data cards; recording provenance, units, and known issues.
- Data-centric iteration: label/feature/data-quality improvements vs. model tuning; measuring impact with a fixed model and tracking each iteration in MLflow.

**Live demo / in-class activity:** Take the C-MAPSS feature set from L7, put it under DVC, and reproduce the exact model input from a clean checkout. Then demonstrate a leakage detector: compare a random split vs. a per-unit split and show the (misleadingly) inflated score from leakage. Log both as MLflow runs tagged with the DVC data version.

**Engineering framing / dataset:** C-MAPSS continued — versioned raw data, versioned engineered features, and split strategies compared head-to-head so the leakage lesson is quantitative, not just cautionary.

**Readings & resources:**
- DVC documentation, "Data Versioning" and "Pipelines (dvc.yaml)."
- Gebru et al., "Datasheets for Datasets" (CACM 2021).
- Kaufman et al., "Leakage in Data Mining: Formulation, Detection, and Avoidance" (ACM TKDD 2012).
- scikit-learn User Guide, "Cross-validation" (TimeSeriesSplit, GroupKFold).

## Teaching notes / common pitfalls
- The single most valuable lesson of the arc is leakage. Make students *produce* a leaky pipeline and see the inflated metric, then fix it — the contrast is what sticks.
- Random `train_test_split` on time-series is the default students reach for; explicitly ban it for temporal/grouped data and require `TimeSeriesSplit`/`GroupKFold`.
- Fitting a scaler before splitting is the most common real bug. Require transformers inside a pipeline fitted on training folds only, and check for it in grading.
- DVC setup (remotes, cache) causes friction; a local DVC remote (a directory) is enough for this assignment. Do not require cloud storage.
- "More features" is not the goal — reproducibility and correctness are. Reward a small, documented, leakage-free feature set over a large undocumented one.
