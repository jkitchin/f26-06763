# Assignment 1 — Reproducible Project Scaffold
**Module:** Week 01 · **Released:** L2 · **Due:** ~1 week later · Part of the 45% assignment pool.

## Goal
Stand up a professional, reproducible Python project from scratch using `uv` and git. You will pull a real engineering sensor dataset, convert a throwaway exploratory notebook into a runnable, importable module with a command-line entry point, and document it so a stranger can rebuild your environment and reproduce your result with two commands. This scaffold becomes the template you reuse all semester.

## Learning outcomes assessed
- Create a deterministic environment with `uv` (pinned interpreter + lockfile).
- Structure a project with a sensible `src/` layout and `.gitignore`.
- Version code appropriately and keep raw data out of git.
- Refactor notebook code into a tested, parameterized script/module.
- Log a run to MLflow and write a clear README.

## Dataset
UCI Air Quality Data Set (De Vito et al., 2008) — hourly responses of a metal-oxide multisensor gas device plus reference concentrations (CO, NOx, benzene). Download from the UCI Machine Learning Repository (`AirQualityUCI.csv`/`.xlsx`). Your code must download or read it from a documented path, not from a copy committed to the repo.
**Fallback:** UCI "Appliances Energy Prediction" dataset (10-min interval building sensor + energy data) if UCI Air Quality is unavailable; document whichever you used.

## Tasks
1. `uv init` a project named `sensorlab` (or similar); pin Python 3.11+ via `.python-version`. Add dependencies (`pandas`, `matplotlib`, `scikit-learn`, `mlflow`) with `uv add` so `uv.lock` is generated.
2. Create a `src/` layout: `src/sensorlab/` package, plus `data/` (git-ignored), `notebooks/`, `scripts/`, `tests/`. Write a `.gitignore` that excludes `data/raw/`, `.venv/`, and MLflow artifacts.
3. Write a small exploratory notebook (`notebooks/explore.ipynb`) that loads the data, handles its quirks (European decimal commas, missing values coded as -200), and produces one figure. It must run top-to-bottom via Restart & Run All.
4. Refactor the notebook logic into `src/sensorlab/` functions (`load`, `clean`, `featurize`) and a runnable entry point `python -m sensorlab.train` that takes CLI args (e.g. `--seed`, `--data-path`), fits a trivial baseline model, and prints/saves a metric.
5. Log the run to MLflow: parameters (seed, data version/date), at least one metric, and the figure as an artifact. Run it twice with different seeds and confirm both appear in the MLflow UI.
6. Write at least one `pytest` test (e.g., `clean` removes -200 sentinels; output has no NaNs).
7. Write a README with setup (`uv sync`), how to get the data, and how to reproduce (`uv run python -m sensorlab.train --seed 0`).

## Deliverables
- A git repository (GitHub link or zip) with the `src/` layout above, `pyproject.toml`, `uv.lock`, `.python-version`, `.gitignore`, the notebook, the module, tests, and README.
- README (≤1 page) covering environment rebuild, data acquisition, and reproduce steps.
- Screenshot or exported view of the two MLflow runs.
- Raw data must NOT be committed.
