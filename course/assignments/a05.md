# Assignment 5 — Model-Selection Study with Tracked Experiments
**Module:** Week 05 · **Released:** L9 · **Due:** ~1 week later · Part of the 45% assignment pool.

## Goal
Take one engineering regression dataset from raw data to a **defended model choice**. You
will build strong baselines, run a systematic model-and-hyperparameter search, track every
run in MLflow, and report a single honest held-out test estimate with uncertainty. The
deliverable is not "the highest R²" — it is a *reproducible, leakage-free study* whose
conclusion you can defend.

## Learning outcomes assessed
- Frame an engineering problem, choose a metric matched to the cost of error, and build
  baselines that must be beaten.
- Select and justify a cross-validation scheme appropriate to the data's structure.
- Avoid data leakage by keeping preprocessing inside a scikit-learn `Pipeline`/CV.
- Instrument runs with MLflow (params, metrics, artifacts, data + code version) so results
  are reproducible and comparable.
- Report results honestly: validation for selection, test touched once, uncertainty stated.

## Dataset
Choose **one** (all are real, small enough to run on a laptop, and documented on the UCI
Machine Learning Repository):

- **Combined Cycle Power Plant** (9,568 rows; ambient temp, exhaust vacuum, ambient
  pressure, relative humidity → net hourly electrical output, MW). Rows ~i.i.d. → k-fold.
- **NASA Airfoil Self-Noise** (1,503 rows; frequency, angle of attack, chord length,
  free-stream velocity, suction-side displacement thickness → scaled sound pressure level,
  dB).
- **Concrete Compressive Strength** (1,030 rows; 8 mix/age features → compressive strength,
  MPa). Note grouping considerations if multiple specimens share a mix.

You may propose a different real engineering **regression** dataset (get it approved). Record
the exact source, version/date downloaded, and a content hash (tie to your Wk4 data-
versioning habit).

## Tasks (numbered, concrete, buildable in a week)
1. **Load & document.** Ingest the dataset into a clean, validated feature table (reuse your
   Wk3 validation). Write a short data card: units, ranges, target, and any grouping
   structure. Log the dataset hash.
2. **Split & baseline.** Create a locked train/test split (and choose your CV scheme on the
   training portion — justify k-fold vs. GroupKFold vs. TimeSeriesSplit). Build at least
   **two baselines**: predict-the-mean and a linear/ridge model. Report their CV metrics.
3. **Choose a metric.** Pick a primary metric (e.g., RMSE) and justify it in engineering
   terms (units, penalty for large errors). Report at least one secondary metric (MAE or R²)
   and look at residuals.
4. **Model families.** Compare at least **three** model families (e.g., linear/ridge, random
   forest, gradient boosting; a k-NN or SVR is fine as a fourth). All preprocessing must live
   inside a `Pipeline` so it is refit within each CV fold.
5. **Hyperparameter search.** Run a systematic search (grid, random, or Optuna) over at least
   one non-trivial model. Use nested runs or a documented protocol so selection is not done
   on the test set.
6. **Track everything in MLflow.** Every baseline, CV fold, and search trial is logged with
   params, metrics, git commit SHA, dataset hash, and seed. Log at least one artifact
   (residual plot or feature importances) and the final fitted pipeline.
7. **Select & test once.** Apply the 1-SE rule (or a stated selection rule) to pick the final
   model, then evaluate it **once** on the locked test set. Report the test metric with an
   uncertainty estimate (CV std, or bootstrap the test error).
8. **Write up.** A short report (≤3 pages) with a results table, your CV-scheme
   justification, a leakage self-audit, and your defended conclusion.

## Deliverables
