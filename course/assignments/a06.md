# Assignment 6 — Train a PyTorch Model on an Engineering Dataset
**Module:** Week 06 · **Released:** L11 · **Due:** ~1 week later · Part of the 45% assignment pool.

## Goal
Build, train, and honestly evaluate a **deep-learning model in PyTorch** on a real
engineering dataset, using a GPU, with the architecture matched to the data's structure. You
must write the training loop yourself (no high-level `Trainer` black box), track training in
MLflow, and compare against a **strong classical baseline** from Week 5. The lesson is as
much "when does DL help?" as "can you train a net?"

## Learning outcomes assessed
- Implement a correct PyTorch training loop (Dataset/DataLoader, forward/backward/step/
  zero-grad) and run it on GPU without device or NaN errors.
- Choose an architecture (MLP / CNN / sequence model) that matches the input structure.
- Apply regularization and stabilization (normalization, dropout, weight decay, LR schedule,
  early stopping) and read loss curves.
- Evaluate with a leakage-free, correctly grouped/time-aware split and compare against a
  classical baseline on the *same* split.
- Track DL experiments in MLflow (per-epoch metrics, best checkpoint, final model) and
  reproduce a run from its config + seed.

## Dataset
Choose **one** (pick a structure you want to practice):

- **NASA C-MAPSS Turbofan (FD001)** — remaining-useful-life regression from 21 sensor
  channels + 3 operating settings over run-to-failure engine cycles. **Sequence model /
  1D-CNN**; **GroupKFold by engine unit** is mandatory. (NASA Prognostics Data Repository.)
- **CWRU Bearing Vibration** — fault classification (normal / inner-race / outer-race / ball)
  from accelerometer time series. **1D-CNN or windowed sequence model**; group by
  recording/bearing.
- **Concrete Compressive Strength** or **Superconductivity** (UCI) — tabular regression with
  an **MLP**; use this if you want a clean DL-vs-tree comparison.
- A 2D **field dataset** (e.g., simulated heat/Poisson source→temperature fields you
  generate, or an approved image-like engineering set) — **2D-CNN**.

You may propose another real engineering dataset (get it approved). Record source, version,
and content hash.

## Tasks (numbered, concrete, buildable in a week)
1. **Data pipeline.** Load the data into tensors via a `Dataset`/`DataLoader`. For time
   series, implement windowing and fit normalization on the **training split only**. Document
   the split and grouping.
2. **Split correctly.** Use GroupKFold-by-unit (turbofan/bearings) or a time-aware split as
   appropriate; hold out a locked test set. Justify the choice in one paragraph.
3. **Baseline.** Reproduce or build a **classical baseline** on the same split (e.g., the Wk5
   gradient-boosting model on hand-crafted window features, or predict-the-mean/persistence).
   This is the bar your net must clear or explain.
4. **Model.** Implement an architecture matched to the data (MLP / 1D-CNN / RNN-LSTM /
   2D-CNN) as an `nn.Module`. Write the training loop by hand.
5. **Train on GPU.** Debug on a tiny subset/few epochs on CPU, then run the full training on
   the provided cloud GPU. Use an LR schedule and **early stopping on validation loss**;
   checkpoint the best model.
6. **Track in MLflow.** Log hyperparameters, seed, git SHA, dataset hash, per-epoch
   train/val loss, the best checkpoint as an artifact, and the final registered model. Log the
   loss-curve plot.
7. **Evaluate honestly.** Report the primary metric (RMSE for RUL, macro-F1/PR-AUC for fault
   classification) on the locked test set — touched once — with uncertainty (across folds or
   seeds). Compare directly to the baseline in a table.
8. **Error analysis.** Show 2–3 concrete failure cases (worst RUL errors / confused classes)
   and hypothesize why. State honestly whether DL beat the baseline and at what cost.
